# JSON Video Player

A browser-based video player that plays structured JSON files instead of real video. Each JSON file describes a sequence of scenes — each scene is a self-contained HTML document with narration text and timing. Videos are generated by an AI agent using a built-in skill pipeline, and can be exported to MP4 via FFmpeg.js.

---

## How It Works

A **JSON video** is a single `.json` file containing:
- A sequence of scenes, each with an HTML slide, speech caption, and duration
- An MP3 audio track embedded as a base64 data URI

The player renders each scene's HTML in an iframe, syncs the audio, and displays captions. Because every scene is just HTML, Claude can generate or edit videos without video editing tools.

## Part 1: Playing Videos

### Quick Start

Open `index.html` in a browser. For basic playback, VS Code's Live Preview extension works:

1. Right-click `index.html` → **Show Preview** → open in browser
2. Click **Load JSON** and select any assembled `script_assembled_base64.json` file (e.g. from `examples/`)
3. Press **Play**

### Enable MP4 Export

MP4 export requires `SharedArrayBuffer`, which needs specific security headers. Use the provided dev server:

```bash
npx http-server . --cors -p 4173 \
  --header "Cross-Origin-Opener-Policy: same-origin" \
  --header "Cross-Origin-Embedder-Policy: require-corp"
```

Then open `http://localhost:4173` and use the **Export MP4** button.

> **Note:** Exported MP4s render at 1280×720 regardless of the JSON `width`/`height` values. Source content is designed at 1600×900 and is scaled down during export.

#### VS Code Live Server (alternative)

Add to VS Code `settings.json`:
```json
"liveServer.settings.CustomHttpHeaders": {
    "Cross-Origin-Opener-Policy": "same-origin",
    "Cross-Origin-Embedder-Policy": "require-corp"
}
```

### GitHub Pages

The repo deploys automatically to GitHub Pages on every push to `main` via `.github/workflows/deploy.yml`. Configure Pages in your repo settings to use the `gh-pages` branch.

## Part 2: Generating Videos

Videos are authored using an **AI agent** with a set of built-in skills. The agent acts as the orchestrator — reading source materials, generating narration, calling external APIs, and saving everything to disc.

### Requirements

- An AI agent CLI or desktop app (e.g. Claude Code)
- Python 3.9+ with packages: `elevenlabs`, `google-api-python-client`, `google-auth`, `httpx`, `python-dotenv`, `xhtml2pdf`, `beautifulsoup4`, `requests`
- API keys in `generation/tools/.env`:

```
ELEVENLABS_API_KEY=your_key_here
GOOGLE_API_KEY=your_key_here
GOOGLE_SERVICE_ACCOUNT_JSON=base64_encoded_service_account_json
```

`GOOGLE_API_KEY` is for Gemini image generation. `GOOGLE_SERVICE_ACCOUNT_JSON` is only needed if fetching from Google Slides or Google Docs.

### The Generation Pipeline

Videos are organized into a unit → lesson → video hierarchy. Setup steps at the unit and lesson level happen once; video creation repeats for each video in a lesson.

```
── One-time setup ───────────────────────────────────────────────────
/unit-init   <unit-slug>              → create unit.json from Code.org API
/lesson-init <unit> <lesson>          → create lesson folder + sources.csv
/lesson-ground <unit> <lesson>        → fetch source materials (slides, docs, levels)

── Per-lesson planning ──────────────────────────────────────────────
/lesson-plan <unit> <lesson>          → analyze objectives, recommend video split,
                                        initialize all video folders  ← human check-in

── Per-video creation ───────────────────────────────────────────────
/video-create <unit> <lesson> <video> → run full pipeline for one video:
  /video-script     → generate scene narration           ← human check-in
  /video-html       → generate HTML slides               ← human check-in
  /video-audio-tags → add TTS expression tags            ← human check-in
  /video-audio      → synthesize MP3 audio               ← human check-in
  /video-assemble   → embed assets, write final JSON
```

Each video's `script.json` stores `unit`, `lesson`, and `target_objectives` so all skills resolve paths deterministically. Source materials in `lesson/source/` are fetched once and shared across all videos in that lesson.

### Step-by-Step: Creating Your First Video

**1. Initialize the unit (one-time)**
```
/unit-init my-unit
```
Fetches lesson IDs from Code.org and creates `generation/units/my-unit/unit.json`.

**2. Initialize the lesson (one-time per lesson)**
```
/lesson-init my-unit my-lesson
```
Creates the lesson folder and a `sources.csv` template listing source materials to fetch.

**3. Fetch source materials (one-time, refreshable)**
```
/lesson-ground my-unit my-lesson
```
Downloads slide thumbnails as PNGs, exports Docs as PDFs, fetches Code.org markdown — all saved to `generation/units/my-unit/lessons/my-lesson/source/`. Can be re-run to refresh.

**4. Plan videos for the lesson**
```
/lesson-plan my-unit my-lesson
```
Claude reads the lesson objectives and source materials, proposes a video split (one video per objective or group of objectives), and initializes all video folders after you approve. This is the preferred entry point — do not run `/video-init` after this.

**5. Create a video**
```
/video-create my-unit my-lesson my-video
```
Runs all production stages in sequence, pausing at each human check-in point. Stages:

- **Script** — Claude asks for a generation mode (concept / summary / re-teach / co-create), generates the narration, and iterates until you approve.
- **HTML slides** — Claude evaluates scenes, picks visual approaches (HTML templates, SVG, AI images), and generates slides after you approve the plan.
- **Audio tags** — Claude adds expression tags for ElevenLabs and Gemini TTS. You review and approve.
- **Audio** — Claude asks which TTS provider and voice to use, then generates MP3 audio.
- **Assemble** — Embeds MP3 audio and any local images as base64 data URIs into the final `script_assembled_base64.json`.

**6. Load in the player**

Open `index.html`, click **Load JSON**, and select `script_assembled_base64.json` from the video folder.

---

### Adding a Single Video Outside a Plan

If you need to add one video to an existing lesson without running `/lesson-plan`:

```
/video-init my-unit my-lesson my-video
```

Then run `/video-create my-unit my-lesson my-video` to produce it.

---

### Shortcut: Run the Full Pipeline

`/video-create` already orchestrates all stages. If the lesson is already grounded and videos are already initialized, just run:

```
/video-create my-unit my-lesson my-video
```

---

### Resuming a Partially-Complete Video

Every skill checks `script.json`'s `pipeline` status and skips completed stages. Run any skill at any time — it picks up where you left off. `/video-create` also resumes automatically.

## JSON Video Format

```json
{
  "video_name": "my-video",
  "unit": "my-unit",
  "lesson": "my-lesson",
  "target_objectives": [
    "Students will be able to explain X.",
    "Students will be able to identify Y."
  ],
  "target_vocabulary": ["term-one", "term-two"],
  "width": 1600,
  "height": 900,
  "pipeline": {
    "grounding": "complete",
    "script": "complete",
    "html": "complete",
    "audio_tags": "complete",
    "audio": "complete",
    "assembled": false
  },
  "tts": {},
  "scenes": [
    {
      "comment": "Scene description",
      "duration": "8.5s",
      "html": "<html>...</html>",
      "speech": "Caption text shown to viewer",
      "elevenlabs": "[excited] Narration text sent to ElevenLabs",
      "gemini": "[excited] Narration text sent to Gemini TTS",
      "audio": "audio/scene_01.mp3"
    }
  ]
}
```

Each scene's `html` field is a complete self-contained HTML document rendered at 1600×900px.

`script.json` exists in two states during production:
- **Pre-assembly** (the working state): per-scene `audio` paths (`"audio/scene_01.mp3"`), local `<img src="...">` paths for images
- **Post-assembly** (after `/video-assemble`): a top-level `"audio": "data:audio/mpeg;base64,..."` replaces the per-scene paths, and all local image paths are replaced with base64 data URIs

Use `base64_clean.py` to strip base64 payloads before asking Claude to read or edit a post-assembled script.

## Tools Reference

These scripts are called by the skills automatically. You can also run them directly if needed. Replace the example path with your actual video path.

### `generation/tools/elevenlabs-gen.py`
```bash
python .agents/skills/video-audio/scripts/elevenlabs-gen.py \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script.json --voice Dan
python .agents/skills/video-audio/scripts/elevenlabs-gen.py \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script.json --fake
```
Reads `scenes[].elevenlabs`, calls ElevenLabs, saves a single `audio/voiceover.mp3`, and writes `scenes[].duration` back to `script.json`. Voices: Dan, Sam, Adam, Hope. `--fake` skips the API call and assigns 3.0s per scene.

### `generation/tools/gemini-audio-gen.py`
```bash
python .agents/skills/video-audio/scripts/gemini-audio-gen.py \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script.json --voice Zephyr
python .agents/skills/video-audio/scripts/gemini-audio-gen.py \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script.json --fake
```
Reads `scenes[].gemini`, calls Gemini TTS, saves per-scene `audio/scene_NN.mp3` files, and writes `scenes[].duration` and `scenes[].audio` back to `script.json`. Voices: Zephyr, Puck, Aoede, Kore, Fenrir. `--fake` skips the API call and assigns 3.0s per scene.

### `generation/tools/gemini-image-gen.py`
```bash
python generation/tools/gemini-image-gen.py "prompt text" --aspect-ratio 16:9
```
Prints the absolute filepath to the generated image on stdout.

### `generation/tools/base64_clean.py`
```bash
python .agents/skills/video-assemble/scripts/base64_clean.py \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script.json
# → writes script_cleaned.json (original untouched)
```
Run before asking Claude to read or edit a script that has embedded images.

### `generation/tools/embed-data.py`
```bash
python .agents/skills/video-assemble/scripts/embed-data.py \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script.json \
  generation/units/my-unit/lessons/my-lesson/videos/my-video/script_assembled_base64.json
```
Embeds all local assets (images and audio) as base64 data URIs. Writes to the output file; source `script.json` is never modified. Auto-detects `tts.mode` to handle per-scene, combined, or fake audio.
